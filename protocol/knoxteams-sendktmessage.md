# KnoxTeams `sendKtMessage` 직접 호출 확인

## 확인 결과

KnoxTeams Electron 애플리케이션 내부의 저수준 `sendKtMessage` 경로를 직접 호출하면 Teams 채널 메시지를 서버로 전송할 수 있다.

- 통신 계층: WSS(WebSocket Secure)
- 메시지 직렬화: Protocol Buffers 바이너리
- 내부 구분: `TCP_KT` Teams 채널 경로
- 서버 응답: MessageKey와 전송시각이 포함된 ACK 수신
- 상대방 수신: 상대방 모바일·PC KnoxTeams에서 실제 메시지 표시 확인

따라서 KnoxTeams의 화면 입력이나 전송 버튼을 사용하지 않고도, 로그인된 애플리케이션의 내부 세션과 저수준 메시지 모듈을 이용한 서버 송신 자체는 가능하다.

## 중요한 한계

`sendKtMessage`를 직접 호출한 메시지는 발신자 PC KnoxTeams의 정식 saga/dispatch 경로를 거치지 않는다.

- 발신자 PC 화면에 보낸 메시지가 즉시 표시되지 않음
- 발신자 PC 로컬 `TB_KtMessage`에 해당 메시지가 저장되지 않음
- 따라서 `teams-record`가 발신자 로컬 DB를 갱신해도 이 메시지를 확인할 수 없음
- 상대방에게는 전달되므로 서버 송신 ACK만으로 발신자 로컬 동기화까지 성공했다고 판정하면 안 됨
- 애플리케이션 재시작이나 서버 이력 재동기화 뒤 발신자 로컬에 들어오는지는 확인하지 않음

이 상태로는 사용자가 보낸 내역을 PC에서 확인할 수 없어 일반적인 실시간 메시지 송신 기능으로 사용하기 어렵다.

## 활용 가능성

완성 기능은 아니지만 다음 연구에는 활용할 수 있다.

- KnoxTeams WSS·Protobuf 송신 프레임 구조 검증
- 서버 ACK, MessageKey, 전송시각 처리 분석
- 수신자 전달 여부만 필요한 제한적 알림 PoC
- 정식 saga/dispatch와 저수준 송신 사이의 차이 비교
- 서버 송신 뒤 발신 클라이언트 동기화에 필요한 추가 이벤트·ACK·조회 호출 추적

## 프로젝트 적용 기준

- 현재 상태: 프로토콜 송신 PoC만 확인
- 제품 기능 상태: 사용 불가
- `teams-record` 기본 기능에 연결하지 않음
- 사용자 KnoxTeams 화면에 키보드·마우스 입력을 주입하는 방식은 사용하지 않음
- 발신자 UI와 로컬 DB 동기화 프로토콜이 확인되기 전까지 자동 송신 기능으로 제공하지 않음
